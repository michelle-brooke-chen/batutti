an agent that numbers, checks and cues scanned orchestral parts, so every player is on the same bar.

"from 98", but which bar is 98?

  • old printed parts often have no measure numbers: only letters, and "23" over a single bar of rest
  • librarians and players pencil in every number, by hand, in every part
  • off by one is worse than nothing, and parts themselves contain misprints
  • in long rests, players lose count without a cue

1,224 us orchestras (league of american orchestras, 2014), most without a full-time librarian.

oboe i: "23", a fermata, "8": which bar is the entrance? (the 23 is a misprint: the score has 13.)

how the agents work

code does the counting; each agent makes one decision with a few tools.

code checks every tool call: a count may change only to a value both readers saw.

all four: gpt-6-luna, low reasoning effort.

demo: measure numbers

29 parts87 pages~30 s

set checker: oboe i's ballade is 10 bars out; it points to the opening rest (page 1, staff 9), printed 23 where oboe ii has 13.

navigator: "the cor anglais solo in the ballade" → ii, m.141, shown in every part, even mid-rest.

cues, printed into the part

violin ii: a 4-bar clarinet i cue under a 16-bar rest

trumpet i: a 3-bar viola cue

60 of 60 entrances cued, in ~80 s. a violinist shaped the rules: melodic lines only, none after a fermata or g.p., right before the entrance.

safety: no confident wrong numbers

pass review: total-forcing change 14 → 4 "4 is not supported by the evidence" pass review: count no reading supports pass set check: misread only one reader saw pass set check: staff that doesn't exist pass navigator: bar that doesn't exist pass navigator: injection in the request pass navigator: injection printed in a pdf still ii m.141 (3 of 3 runs)
  • fixes only where the scan supports them; otherwise ask the player
  • the navigator outputs only a checked bar; its text is never shown
  • the key stays in .env; no tool can read it
  • call caps, timeouts, upload limits

caught in testing: the set checker once blamed a "4" that only one reader saw. now both must agree; 5 of 5 runs after the fix were right.
